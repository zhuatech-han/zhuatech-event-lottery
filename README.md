## 功能

- 扫码自助签到、同名合并、结束或重新开放签到；主办方可删除活动及服务器上的签到记录。每场最多 2,000 人。
- 最多设置 20 个奖项，随机抽取且不重复中奖；全屏投放、导出中奖 CSV。
- 自选大屏主题，或上传 JPG/PNG/WebP 背景图并调整位置与压暗程度。背景图只保存在当前浏览器。
- 导出活动备份后，可在同一站点换设备恢复管理权限、手动名单、奖项和中奖结果。
- 手动名单、奖项和中奖结果保存在主办方当前浏览器；扫码签到记录保存在活动服务中。活动链接有效期为 30 天，过期后不能继续访问；活动结束后可主动删除。

扫码签到由参与者自行填写，不核验到场身份。相同姓名只能签到一次，同名不同人请补充部门或编号。参与者不应填写手机号、身份证号等敏感信息。

## 本地运行

需要 Node.js 24 或更高版本。运行：

```sh
npm run dev
```

打开 `http://127.0.0.1:4173/`。本地预览使用项目目录内的 `.local/events.sqlite` 保存测试签到记录；手机不能通过自身的 `127.0.0.1` 扫码访问电脑上的预览页。供参与者扫码时，应把站点部署到参与者手机可访问的地址。仅本人可访问的私有预览不能用于外部现场签到。

检查代码和功能：

```sh
npm run lint
npm test
npm run build
```

详细步骤见 [操作手册](docs/操作手册.md)。站点的服务端使用 D1 数据绑定 `DB`；部署时应将数据库绑定命名为 `DB`，无需在仓库提交真实密钥。

## 自行部署扫码服务

浏览器保存奖项、中奖结果和活动管理凭证；服务端数据库保存活动与签到名单。`dist/` 中的网页和脚本是源码，`worker/` 是 D1 接口，`worker/migrations/001_events.sql` 是首版表结构，`scripts/` 提供 Node.js 24.19+ 的 SQLite 适配与构建，`tests/` 验证接口和备份，`docs/` 保存手册及真实截图。独立部署不依赖原试用平台。

```sh
docker compose up --build -d
# 默认 http://127.0.0.1:4173/；端口占用可设置 WEB_PORT=18173
```

Compose 使用 Nginx 代理同源网页及 `/api`，SQLite 数据保存在 `lottery_data` 卷，服务及数据库健康检查为 `/health`。配置名称见 [.env.example](.env.example)：容器入口使用 `WEB_PORT`、`WEB_BIND_ADDRESS`；直接运行 Node 服务时使用 `HOST`、`PORT`、`DB_PATH`。本机监听地址不能被另一部手机访问。实际活动须配置手机可访问的域名、HTTPS 和访问限制，并在活动前试扫。没有短信、支付或付费模型依赖。

没有共享的管理员登录账号或默认密码。活动创建者获得独立随机管理凭证，数据库只保存其哈希；公众只能签到，名单读取、关闭和删除均校验凭证。活动管理凭证不能分享给参与者。此版本不是组织账号管理系统，没有角色编辑、部门、经营仪表盘或全局管理后台；README 截图对应主办方工作台、大屏和签到页，没有虚构的登录或权限设置页。

首次请求或健康检查自动执行版本 1 的幂等迁移，并兼容原版活动与签到表；记录在 `schema_migrations`。已有更高版本数据库会被拒绝，不能直接降级。升级前停止该服务并备份数据卷；重启后检查 `/health`、原活动和签到名单。活动备份包含管理凭证，只供私下保存；中奖 CSV 不包含管理凭证。正式活动前应演练数据卷恢复。

## 故障与维护

扫码无法访问时先检查参与者手机能否打开部署域名、HTTPS 和网络；源代码自行部署不要求连接原试用域名。名单不同步时确认活动未过期、未关闭，主办方浏览器仍持有管理凭证。端口占用时覆盖 `WEB_PORT`。请求体和签到人数有上限，不能绕过限制做批量个人信息收集。

贡献流程见 [CONTRIBUTING.md](CONTRIBUTING.md)，问题在仓库 Issue 中提供脱敏步骤，漏洞按 [SECURITY.md](SECURITY.md) 私下反馈。软件按现状提供，扫码签到不验证真实身份，抽奖算法不构成公证或监管认证。活动主办方负责活动规则、参与者告知与数据保管。

发布资料检查：`node scripts/verify-release.mjs`。此检查核对图片、原二维码、授权与示例配置；业务和部署仍须执行上文的实际验收。
